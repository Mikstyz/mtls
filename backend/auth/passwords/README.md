# Начальный список запрещённых паролей

`common-passwords.txt` — локальная подборка из 11 157 разных строк, собранная из двух публичных списков SecLists: [100k NCSC](https://github.com/danielmiessler/SecLists/blob/85f196c09ac053a3d00074433f28807abf45bc50/Passwords/Common-Credentials/100k-most-used-passwords-NCSC.txt) и [Xato 1M](https://github.com/danielmiessler/SecLists/blob/85f196c09ac053a3d00074433f28807abf45bc50/Passwords/Common-Credentials/xato-net-10-million-passwords-1000000.txt). Копия лицензии — `LICENSE-SecLists`.

Из исходных файлов выбраны печатные строки длиной от 15 символов и не более 1024 байт UTF-8; дубликаты удалены. Более короткие пароли уже отклоняет политика auth. Входные SHA-256: NCSC — `c2e5696882c603b76bb67a47ee970897e5a76fc4c3f5547abe3d0ca340c576e0`, Xato — `424a3e03a17df0a2bc2b3ca749d81b04e79d59cb7aeec8876a5a3f308d0caf51`.

Укажи путь к этому файлу в `[services.auth.password].blocklist_path`. Относительный путь считается от каталога файла конфигурации: для корневого `config.toml` это `backend/auth/passwords/common-passwords.txt`. Можно также указать абсолютный путь. Auth загружает список при запуске и сравнивает пароль локально, без сетевой передачи.

Это начальный снимок известных слабых паролей, а не полный или автоматически обновляемый список всех утечек. Источники содержат исторические данные; перед публичным запуском необходимо организовать получение и обновление актуального корпуса. Файл можно заменить на более полный UTF-8 список: один пароль на строку, не более миллиона различных хешей исходных и NFC-форм и 64 МиБ.

## Проверка и обновление

Периодически проверяй источники на обновления и пополняй локальный список доверенным корпусом распространённых и скомпрометированных паролей. Сохраняй сведения об источнике, версии, лицензии и контрольной сумме; не отправляй в источник пароли пользователей. Перед заменой проверь формат, ограничения выше и права файла, затем разверни одинаковую версию на всех экземплярах auth и поочерёдно перезапусти их. Наблюдай ошибки загрузки и регистрацию; прежнюю проверенную копию храни для отката с теми же ограничениями доступа. Частота проверки и ответственный должны быть назначены при развёртывании — автоматического обновления пока нет.

В `[services.auth.password]` настрой `normalize_unicode = true`, чтобы новые и изменённые пароли перед хешированием приводились к NFC. Старые пароли версии 1 сначала проверяются по исходным байтам и после успешного входа безопасно обновляются до версии 2; до первого входа эквивалентная запись Unicode не заменяет старый пароль. Сравнение нового пароля с блок-листом учитывает NFC. Чтение обеих версий поддерживается даже при `normalize_unicode = false`.

Для нескольких экземпляров сначала разверни эту версию auth на всех экземплярах с `normalize_unicode = false`, проверь совместимость, затем включи настройку и перезапусти экземпляры. После появления версии 2 возврат к старому коду auth, который её не поддерживает, заблокирует вход таких аккаунтов; просто отключить настройку недостаточно для такого отката. Для этой настройки не требуется новая миграция БД.

# Регистрация: проект реализации

Реализованы создание выключенной учётной записи, очередь SMTP-писем, подтверждение email с выбором пароля и фоновое создание профиля. До публичного запуска необходимы полная проверка с реальными сервисами и итоговое ревью.

## Состояния

Auth владеет жизненным циклом регистрации и учётными данными. При начале регистрации он создаёт выключенную учётную запись и ограниченную по времени задачу подтверждения email. Логин и адрес резервируются уникальными ограничениями БД. Владелец почты выбирает пароль после перехода по ссылке, чтобы инициатор регистрации чужого адреса не мог заранее установить известный ему пароль. Пароль сохраняется только в виде Argon2id-хеша с уникальной солью. При отказе доставки регистрация остаётся незавершённой и не даёт входа.

После одноразового подтверждения email auth фиксирует подтверждение и запускает подготовку профиля в user. До успешного создания профиля учётная запись остаётся выключенной. После подтверждённого ответа user auth атомарно переводит регистрацию в активное состояние и включает учётную запись. Один только ответ HTTP не является доказательством отсутствия побочного эффекта: повтор после тайм-аута использует тот же ID и параметры профиля.

Неподтверждённые регистрации имеют срок 24 часа, после которого они очищаются. Подтверждённые регистрации не удаляются автоматически: создание профиля повторяется до успеха или до паузы после 100 попыток. Оператор может безопасно возобновить обработку после устранения сбоя; инструкция — в `backend/OPERATIONS.md`.

## Подтверждение и доставка

Для отправки выбирать настраиваемый SMTP-сервер с проверкой TLS; реальные адрес, учётные данные и отправитель задаются конфигурацией отдельно для auth. В локальной разработке нужен отдельный безопасный режим или тестовый сервер, без ослабления защиты боевой конфигурации.

Верификационный токен генерируется криптографически стойким генератором и проверяется по хешу. До отправки его копия зашифрована отдельным ключом в очереди; после успешной отправки она удаляется. Подтверждение использует атомарное погашение токена. Открытие ссылки само по себе не подтверждает аккаунт: пользователь должен задать пароль и отправить форму.

Сохранение регистрации и задачи доставки выполняется одной локальной транзакцией auth; SMTP-вызов выполняется вне транзакции. Повторы ограничены и безопасны при падении между отправкой письма и сохранением результата. Возможна повторная отправка письма: нельзя предполагать доставку ровно один раз. Токены, пароли и содержимое писем не попадают в логи.

## Границы и проверки

- Логин, email, пароль и ник валидируются до записи. Ответы на публичные запросы не должны раскрывать существование аккаунта; применяются ограничения частоты.
- Для обработки очереди несколькими экземплярами нужны блокировки или аренда работы с истечением срока, чтобы после падения другого процесса задача была повторена.
- Восстановление, удаление и регистрация должны иметь согласованные состояния. Перед повторным включением удалённой учётной записи необходимо отозвать старые сессии; `enabled` сам по себе этого не делает.
- Auth выдаёт внутреннему запросу срок действия аренды, а user проверяет его после общей блокировки с операциями удаления. Просроченный запрос не может воссоздать профиль после очистки служебной записи. Часы серверов должны быть синхронизированы.
- Проверить одновременную регистрацию одинаковых адресов и логинов, дубли подтверждения, отказы SMTP и user, тайм-аут после успешного создания профиля, остановку и повторный запуск обработчика.

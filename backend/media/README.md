# Media: внутренняя выдача файлов

Прототип на Rust выдаёт уже подготовленные фото, видео и HLS-файлы из локального каталога. Приём и обработка загрузок, управление правами, поиск и публикации находятся вне его задач. Перед чтением файла сервис запрашивает проверку прав в user, который проверяет сессию и состояние владельца через auth.

**Сервис пока нельзя открывать пользователям и считать готовым к production.** Общий секрет подтверждает доверенный вызывающий компонент; помимо него каждый запрос должен содержать сессию пользователя. Media спрашивает user о праве на данный UUID перед каждым файлом, манифестом и сегментом. Управление правами и публикация готовых файлов ещё не подключены к контуру загрузки. Сейчас сервис принимает соединения только с loopback-интерфейса, межсерверный mTLS не реализован. Сетевые ограничения действуют только на этот внутренний endpoint.

## Конфигурация

Конфигурация читается из общего `config.toml` либо из файла, переданного через `-config`. Для самостоятельного развёртывания можно оставить в конфиге только эти разделы:

```toml
[media]
type = "dir"
directory = "media_dir"

[services.media]
host = "127.0.0.1"
port = 8084
internal_secret = "ЗАМЕНИТЬ_НА_СЛУЧАЙНЫЙ_СЕКРЕТ"
internal_secret_previous = ""
max_streams = 64
max_connections = 128
header_timeout_seconds = 5

[services.media.user]
url = "http://127.0.0.1:8081"
cookie_name = "__Host-mtls_session"

[resources]
max_procs = 0
memory_limit_bytes = 0
```

Каталог должен существовать; относительный путь считается от расположения конфига. Для примера в корневом конфиге используется `media_dir/`, исключённый из Git. Для настоящих файлов предпочтителен отдельный каталог за пределами репозитория и webroot. `type = "api"` пока не поддерживается. Секрет должен состоять из 32–128 печатных ASCII-символов: например, создать отдельное случайное значение через `openssl rand -hex 32`. Храните конфиг с правами доступа только для владельца и не передавайте секрет браузеру. Для ротации сначала укажите новый `internal_secret` и старый `internal_secret_previous` на всех экземплярах media и перезапустите их; после этого переведите вызывающие сервисы на новый секрет. Убедившись, что старый секрет больше не используется, очистите `internal_secret_previous` и снова перезапустите media. Оба непустых секрета проверяются одинаковыми правилами.

`max_streams` ограничивает одновременно открываемые файлы и действующие потоки (1–1024); при исчерпании возвращается 503. `max_connections` ограничивает одновременные TCP-соединения (1–4096): лишние соединения закрываются. `header_timeout_seconds` ограничивает получение заголовков (1–60 секунд); максимальный буфер заголовков — 16 КиБ. HTTP keep-alive отключён, поэтому каждое соединение обслуживает один запрос. `max_procs = 0` выбирает число рабочих потоков автоматически, иначе задаётся явно. `memory_limit_bytes` пока не применяется: при ненулевом значении сервис выводит предупреждение. Ограничение памяти необходимо установить средствами ОС, например cgroup. Проверка запуска и файловых флагов выполнена на Linux.

Запуск из каталога `backend/media`:

```text
cargo run -- -config ../../config.toml
```

## Контракт текущего прототипа

Файлы размещаются по схеме `<directory>/<UUID>/<имя>`; UUID должен быть ненулевым, имя — не длиннее 128 символов, только строчные латинские буквы, цифры, `_`, `-` и `.`. Поддерживаются расширения `jpg`, `jpeg`, `png`, `webp`, `avif`, `mp4`, `webm`, `m3u8`, `m4s`, `ts`. Тип ответа определяется расширением, поэтому контур обработки обязан проверять фактическое содержимое перед публикацией. Пустые, частично записанные или непроверенные результаты не должны попадать в выдаваемый каталог. Только доверенный обработчик должен иметь право изменять его содержимое; сервис не защищает от вредоносных жёстких ссылок, созданных имеющим такие права процессом.

Доверенный компонент обращается к `GET /internal/files/{UUID}/{имя}` или `HEAD` с `X-Internal-Secret` и cookie сессии. Media пересылает только эту cookie в `GET /api/users/media/{UUID}/access`; без подтверждения user и auth файл не открывается. User URL пока должен быть локальным HTTP с числовым loopback-адресом; cookie должна совпадать с настройкой auth. Сервис отклоняет неправильный секрет, пути вне разрешённой схемы, символические ссылки и необычные файлы. Успешный ответ содержит `Cache-Control: private, no-store` и `X-Content-Type-Options: nosniff`. `GET` поддерживает один диапазон байтов с ответами 206 и 416, `HEAD` возвращает метаданные без тела. При `If-Range` возвращается полный файл; ETag и условия кэширования пока не реализованы. Выдача потоковая, без загрузки всего файла в память. `GET /health` возвращает 204.

Манифесты и сегменты HLS могут выдаваться как файлы, но сервис не создаёт и не проверяет манифесты. Их содержимое и ссылки должен валидировать доверенный контур обработки; права необходимо проверять и на манифест, и на каждый сегмент. Пока доступны только запросы с действующей сессией; платные права и самостоятельный публичный доступ ещё не реализованы. Запись готовых файлов должна быть атомарной, а опубликованный файл — неизменяемым на время выдачи.

На SIGINT/SIGTERM сервис прекращает приём новых соединений и ждёт завершения действующих до 15 секунд. Основа интеграции с content описана в `INTEGRATION.md`. Остальные задачи и ограничения перечислены в корневых `TASKS.md` и `MEDIA_PLAN.md`.

Для файла из публикации используйте `GET /internal/posts/{post}/files/{id}/{name}`. Media требует внутренний секрет и cookie, затем перед открытием файла передаёт ID публикации и файла в user. User подтверждает актуальные права по данным auth и content. `HEAD` и запросы с диапазонами требуют той же проверки. Отдельный `/internal/files/{id}/{name}` оставлен для доступа к файлу вне публикации и не использует публичность постов.

Для активного просмотра фото или видео используйте `GET /internal/posts/{post}/playback/{id}/{name}`. Маршрут проверяет такие же права, как обычная выдача файла. Media учитывает объём отправляемого тела. Для фото порог составляет до 64 КиБ при запросе всего файла, для видео — до 256 КиБ. HEAD, плейлисты и адрес обычной выдачи подходят для предварительной загрузки без регистрации просмотра.

Включите отправку просмотров через `[services.media.views]` с `url` content на loopback и отдельным `secret`. Перед включением должны работать обновлённые user и content. Очередь из 256 событий работает в памяти с ограниченным параллелизмом и повтором. При переполнении, перезапуске или длительном отказе content часть событий может быть потеряна, выдача файлов продолжается. Счётчик отражает выдачу файла и подходит для пользовательской статистики.

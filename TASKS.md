# План до готового backend API

Это единственный активный список работ. [PRODUCT_PLAN.md](PRODUCT_PLAN.md) задаёт сценарии сайта, [BUGS.md](BUGS.md) фиксирует дефекты. Первый пункт ниже задаёт следующий шаг. Подробности прежних прогонов сохранены в [архиве](docs/archive/backend-verification.md).

**Порядок:** закончить и сквозным прогоном проверить функциональность → оформить и проверить внешний API → подготовить Docker, Kubernetes и расчёт нагрузки. Прокси и общий мониторинг идут отдельно. Frontend начинается после готовности API. Native отменён.

## 1. Функциональность и проверки

- [ ] **Следующий шаг — связать весь путь медиа на одном стенде.** Реальный вход → резервация → PATCH с обрывом и продолжением → обработка фото и видео → публикация → выдача и поиск → удаление владельцем → отзыв, физическая очистка и исчезновение из поиска. Проверить выбранную обложку, HLS и Range, изоляцию двух пользователей, повтор последней части, неготовый файл и отказ зависимого сервиса. Запускать штатные процессы с ограниченными ролями. Отдельно уже проверены вход и PATCH, путь от HTTP DELETE до исчезновения из Rust search и путь фото от sandbox-обработки до Range. Временный PostgreSQL-стенд подтвердил реальную sandbox-обработку видео до события ready с 720p и HLS. Осталось связать готовое видео с HTTP-публикацией, выдачей, поиском и отзывом.
- [ ] **Публикации и выдача.** Проверить на том же стенде отложенную публикацию и отмену, страницу автора, фото-, видео- и смешанную ленты, короткие и длинные видео, рекомендации, поиск с подсказками и курсорами, лайки, просмотры, избранное и комментарии. Включить отзыв доступа, снятие публикации и замену файла. Для старых видео без длительности или превью сделать отдельный офлайн-проход: безопасно проверить оригинал и записать файл/манифест, повторно доставить метаданные в user, обновить длительность старой публикации в content; проверить повтор, удаление в гонке и отказ между БД и диском.
- [ ] **Аккаунты и очистка.** Пройти регистрацию и почту, вход и серверные сессии, устройства, онлайн и приватность, смену/сброс пароля. Проверить восстановление владельцем до 14 суток, модератором до двух календарных месяцев суммарно, затем очистку профиля, файлов, публикаций, прав, истории и индекса. Проверить отказ сервиса и повтор заданий.
- [ ] **Продажи и реклама.** Повторить покупку отдельной публикации, историю заказа, выдачу и отзыв прав, отключение тестового режима, бюджет и паузу рекламы, защиту от повторов и дневной отчёт ad_operator. Продажи подтверждаются только в явно изолированном тестовом режиме до подключения настоящего провайдера. Подписка автора и подтверждённые донаты остаются открыты. Тестовый заказ не должен давать реальные платёжные права или баллы.
- [ ] **Модерация и рейтинг.** Пройти жалобу, срочное скрытие, защищённый просмотр, решение, уведомление, независимую апелляцию и возврат баллов для поста, комментария и профильного изображения. Проверить пороги 50/70/80/90%, последовательные баны, истечение при нулевом балансе, начисление за подтверждённую активность и отключённые по умолчанию рекламные начисления. Проверить отказ участнику дела и повтор доставки.
- [ ] **Защита 18+ и обращения.** Закрыть проверку возраста зрителей, возраста и согласия участников, отзыв согласия и альтернативный канал для закрытых материалов без сессии. Есть внутренний анонимный приём для публичных постов. Для браузерной формы нужно ограничение частоты на входе. Применимые требования проверяются до публичного запуска.
- [ ] **Релизная проверка.** Закрыть критические позиции [BUGS.md](BUGS.md). Проверить обновление и чистую схему, ограниченные роли, отказы и гонки, резервное копирование и восстановление с WAL, сверку индекса, отзыв восстановленных сессий и удаление данных. Провести итоговое ревью Go/Rust/SQL и безопасности. Описать границы проверенного развёртывания и ограничения, которые влияют на выпуск. Сверить нерешённые детали по пунктам разделов auth/user и медиахранилища в архиве: неполный WAL, сроки очистки копий, актуальность списка скомпрометированных паролей, старые схемы, неподдерживаемые топологии и локальные блокировки.

## 2. Внешний API

- [ ] Подготовить версионированный OpenAPI в backend/api/ по карте продукта и рабочим маршрутам. Описать cookie/CSRF, роли, ошибки, лимиты, курсоры, загрузку частями, HLS/Range и изоляцию тестовых продаж. Черновик `backend/api/openapi.yaml` уже фиксирует загрузку media и браузерные маршруты auth, включая удаление и восстановление аккаунта; профили, публикации, поиск, выдачу и проверку контракта на HTTP ещё нужно добавить.
- [ ] Проверить контракт на запущенном стенде: маршруты, тела, коды и права, скрытие контента, пустые выдачи, повторы и отзыв. Указать порядок миграций, настройки и ограничения для фронтенда. Служебные маршруты и секреты остаются на сервере.
- [ ] Считать API готовым после проверки сценариев раздела 1, сверки контракта с HTTP и закрытия критических проблем для заявленного режима работы. Публичный запуск также требует проверки условий по защите 18+, данным и инфраструктуре.

## 3. После готового API

- [ ] Подготовить Docker и Kubernetes для сервисов, воркеров и хранилищ: миграции, секреты, готовность, завершение, обновление и восстановление. Для нескольких узлов закрыть mTLS в маршрутах, сейчас ограниченных loopback, и согласовать блокировки и хранение media. Для режима media.type=api нужен собственный сервис хранения.
- [ ] Рассчитать ёмкость для 1 млн аккаунтов по пиковому онлайну, RPS, потокам и битрейту, загрузкам и росту хранилища. Замерить популярное видео, backlog, масштабирование и отказ узла. Число реплик и ресурсы определить по измерениям.
- [ ] Прокси и общий мониторинг добавить отдельным этапом.

## Постоянные требования

- Самостоятельное размещение с исключением для почты. Auth отвечает за сессии, user за текущие права и профили, media за выдачу, media-processing за приём и обработку, content за публикации, search за кандидатов. PostgreSQL хранит состояние и транзакционный outbox. Kafka служит транспортом событий, Redis дополняет кэширование и ограничения.
- Хранить оригиналы фото и видео. Фото получает уменьшенный вариант. Видео ниже 1080p хранится в исходном качестве, более качественные исходники получают варианты вплоть до 720p. Оригинал доступен по явному выбору с правами и автоматически для популярных постов. Видео получает автоматическую обложку, выбранный кадр или фото автора.
- Аккаунт использует email, логин, ник и пароль. Сервисы читают собственные разделы TOML. Общие настройки БД наследуются, имя БД задаётся отдельно. Пустые настройки ресурсов оставляют системные значения.
- Следовать [AGENTS.md](AGENTS.md). Проверять ожидаемое поведение и реальные границы доступа. Писать читаемый Go/Rust/SQL, использовать стандартное форматирование и параметризованные запросы, удалять временные проверки.
- [Правила модерации и категории](docs/archive/backend-verification.md#жалобы-и-решения) сохранены из прежнего плана. Жалобы на возраст и согласие приоритетны. Предварительное скрытие выполняет модератор. Баллы списываются после подтверждённого решения.

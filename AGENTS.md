# Работа в проекте

- Временные скрипты, результаты проверок и другие рабочие файлы размещайте в `tmp/` в корне проекта. Каталог исключён из Git; после работы удаляйте созданные временные файлы.
- Если инструмент требует разместить временный файл в другом месте (например, Go-тест рядом с пакетом), удаляйте такой файл сразу после проверки. Постоянные тесты без необходимости или запроса пользователя не добавляйте.
- Код должен быть безопасным и читаемым: используйте стандартное форматирование языка, отделяйте проверки и смысловые блоки пустыми строками. При написании учитывайте производительность и реальные границы безопасности.
- Для временных каталогов инструментов задавайте `TMPDIR=<корень проекта>/tmp`, для Go-кэша — `GOCACHE=<корень проекта>/tmp/go-build-cache`, для временной сборки Rust — `CARGO_TARGET_DIR=<корень проекта>/tmp/cargo-target` (подставляйте абсолютный путь к корню текущего checkout). Временные БД, их сокеты и логи также создавайте внутри `tmp/`. Не переносите и не удаляйте обычные зависимости и файлы пользователя без необходимости.

- Проект рассчитан на собственное размещение: не вводите обязательные сторонние API или управляемые облачные службы, кроме отдельного сервиса отправки почты. Остальные компоненты владелец должен иметь возможность развернуть и контролировать сам; внутренние API собственных сервисов допустимы. SMTP для доставки писем и DNS могут взаимодействовать с внешней инфраструктурой по необходимости.

- Каждый обнаруженный при работе баг сразу записывайте в `BUGS.md`: условия, последствия и статус. После завершения текущей связной части работы исправляйте подтверждённые баги, проверяйте исправление и обновляйте запись. Нерешённые баги не скрывайте и не отмечайте исправленными без проверки.

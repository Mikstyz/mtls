# MTLS

Заготовка проекта с Go-микросервисами, Rust-прокси, React-фронтендом и нативной частью на Rust. Сейчас подготавливается структура; бизнес-логика и интеграция компонентов ещё не реализованы.

## Backend

- `backend/user`, `backend/auth`, `backend/content` — отдельные Go-модули для пользователей, авторизации и контента или продуктов. В каждом есть `cmd/server`, `internal` с базовыми каталогами и `tests`.
- `backend/proxy` — отдельный Rust-пакет для будущего обратного прокси; в `src` подготовлены каталоги конфигурации, маршрутизации, балансировки, подключения к сервисам и middleware.
- `backend/shared` — отдельный Go-модуль для общего кода, когда он действительно понадобится. `backend/api` — место для контрактов, `backend/deployments` — для конфигурации развёртывания.
- `backend/go.work` объединяет Go-модули при локальной разработке. Имена модулей `mtls/...` пока условные: перед публикацией или самостоятельным подключением модулей их следует заменить на реальные пути репозиториев. Общий код не должен объединять бизнес-логику независимых сервисов.

## Приложения

- `frontend/src` — React: `components`, `pages`, `hooks`, `services`, `assets`, `styles`. Публичные статические ресурсы находятся в `frontend/public`.
- `native/src/logic`, `native/src/ui`, `native/src/api` — заготовки логики, интерфейса и обращений к API. Технология нативного интерфейса ещё не выбрана.

Пустые каталоги не сохраняются в Git до появления в них файлов. Структуру можно менять по мере появления реальных требований; сами папки не обеспечивают независимость сервисов. Границы данных, контракты, развёртывание и взаимодействие сервисов предстоит определить отдельно.

## Инструменты

Для разработки понадобятся Go 1.23+, Rust с Cargo и Node.js 20.19+ или 22.12+. Во фронтенде зависимости устанавливаются командой `npm install` из каталога `frontend`. Прокси и нативная часть пока содержат только заглушки; API сервисов не реализован.

## Локальная конфигурация

В корневом `config.toml` можно указать адрес прокси, адреса сервисов, общие драйвер и порт БД в `[database]` и отдельные параметры подключения для каждого сервиса. Порты баз, тип СУБД и учётные данные заполняются после выбора базы данных. Файл не попадает в Git, так как может содержать пароли; при клонировании его потребуется создать заново. Это заготовка: чтение конфигурации и запуск по её параметрам ещё не реализованы.

Раздел `[media]` задаёт место хранения медиа: при `type = "dir"` укажите путь в `directory`, при `type = "api"` — адрес в `api_url`. Пока это только параметры: подключение хранилища ещё не реализовано.
